# BBBuddy 伙伴资料库

> 用途：维护伙伴页当前真实使用和后续扩充的伙伴设定、立绘姿态提示词、图片资产占位和后续生成记录。
> 当前状态：C01-C20 已接入 App；C21-C40 已进入模型，图片可后补，未补图前 App 使用占位图形。

## 总览

本资料库覆盖 `BabyCompanion.all` 中当前已接入的 40 个伙伴（C01-C40）。其中 C01-C10 为 onboarding 气质测评伙伴，C11-C20 为首批扩充伙伴，C21-C40 为第二轮扩充伙伴。另有备选方案/候补变体（同一物种的气质变体或与现有 Buddy 高度相似的候选），不占用正式编号，存放在"备选方案 / 候补变体"区域。后续逐个生成新立绘后，优先把最终透明 PNG 放入 asset catalog，再在这里补充生成版本、最终文件名和备注。

立绘提示词只描述 BBBuddy app Buddy 的动作和姿态，不包含风格词、画风词、材质词、镜头词。所有 Buddy 都是拟人动物，整体为 6 到 12 个月宝宝的可爱比例，只使用站姿或坐姿，不四脚着地；不出现任何道具、文字、icon、特效、树木、自行车等外部元素；同时保留耳朵、尾巴、口鼻、翅膀、花纹等核心动物特征。

伙伴编号使用 `C01` 起的稳定编号。前 10 个按 onboarding 气质测评结果里的动物顺序排列；测评结果直接使用伙伴页 ID 与名称；未进入测评结果的补充伙伴也必须保留明确气质类型，并按扩充顺序顺延编号。


## C01-C20 命名与设定规则

以下规则由 C01-C20 的已稳定 Buddy 设定反推而来，后续新增正式 Buddy 时优先遵守。C21 之后的网络热门候选如果不符合这些规则，应先作为候补或备选，不要直接进入正式编号。

### 编号规则

- `C01-C10` 固定为 onboarding 气质测评伙伴，不调整顺序，不替换 ID。
- `C11-C12` 固定为当前非 onboarding 常驻/补充伙伴，必须保留明确气质。
- `C13-C20` 固定为首批扩充伙伴，作为后续扩充命名、文案、资产规则的样板。
- `C21-C40` 固定为第二轮扩充伙伴，命名优先遵守“英文物种词根关联”。
- 新增正式 Buddy 从当前最大正式编号继续顺延；同一物种的气质变体、季节变体、视觉备选不占正式编号，应放入“备选方案 / 候补变体”区域。

### ID 规则

- onboarding 伙伴沿用历史 ID，例如 `bunny_lulu`、`fawn_mimi`、`otter_tangtang`，不得为了统一格式而重命名。
- 非 onboarding 新伙伴使用稳定 snake_case：`animal_name` 或 `species_name`。
- ID 不使用临时数字后缀，例如 `dun2`、`sasa2`、`rin2`。
- ID 一旦进入正式编号，不应再修改；后续资产、存档、招募记录都可能依赖它。

### 中文名规则

- 中文名以 2 个字为优先，读起来柔软、亲近、适合儿童陪伴语境。
- 避免生僻字、难读字、过度网红化或过强成人感的名字。
- 同组名字应避免重复听感；例如已有洛噗、柯噜、欧缇、阿考、尤卡、雪溜、绵塔、泡露等，不再大量使用同尾音。
- 中文名可以弱关联动物特征，但不要过度直白；例如“糖飞”可以暗示蜜袋鼯，“栗栗”可以暗示小刺猬。

### 英文名规则

- 英文名优先 4-6 个字母，便于 UI 展示和资产命名。
- 首字母大写，资料库中作为展示名；资产名中统一转小写。
- 避免和已有英文名过近：Loppy、Sika、Cal、Moye、Ottie、Fenny、Reddy、Ako、Hoffy、Chippy、Yuca、Ferry、Minta、Rocky、Poro、Lili、Pino、Mika、Shushu、Taffy。
- 如果英文名包含重复音节，如 Shushu，资产名仍使用完整小写：`companion_shushu_portrait`。
- 英文名必须优先能从英文物种/品种核心词反推回来，例如 `Fennec -> Fenny`、`Call duck -> Cal`、`Chipmunk -> Chippy`、`Yucatan miniature pig -> Yuca`。中文名再基于英文名做拟音或轻语义化。

### 物种命名规则

- 物种字段使用“具体动物 + 宝宝”，如“羊驼宝宝”“小海豹宝宝”“小蜜袋鼯宝宝”。
- 能明确到具体物种或品种时，优先写清楚，例如“荷兰垂耳兔宝宝”“亚洲小爪水獭宝宝”“昆士兰考拉宝宝”。
- 如果当前是泛称，必须在现实分布或备注中说明后续接入前需要细化物种，例如“小刺猬宝宝”。
- 避免多个正式 Buddy 使用高度相似物种；相似候选应说明差异，或放入候补变体。

### 气质规则

- 每个 Buddy 必须有且只能有一个气质类型：`easy`、`intermediate`、`slow_to_warm_up`、`high_sensitivity`。
- `easy`：稳定、亲近、温和、低冲突，适合轻松陪伴。
- `intermediate`：状态多变、好奇、有主见，需要弹性回应。
- `slow_to_warm_up`：慢热、谨慎、先观察，需要安全感和过渡时间。
- `high_sensitivity`：敏锐、反应快、容易被环境影响，需要安抚和提前预告。
- 非 onboarding 伙伴不能再写“补充设定”作为气质；补充设定只能作为设定来源。

### 稀有程度规则

- 稀有程度使用 App 内已有四档：`普通`、`少见`、`稀有`、`珍稀`。
- 野生物种以已知的野生存世数量为第一判定依据；数量来源应优先采用 IUCN、政府或物种保护组织的最近公开估计。

| 稀有程度 | 心数 | 野生存世数量 |
|---|---:|---:|
| 普通 | ❤️ | 100 万只以上 |
| 少见 | ❤️❤️ | 10 万至 99.9 万只 |
| 稀有 | ❤️❤️❤️ | 1 万至 9.9 万只 |
| 珍稀 | ❤️❤️❤️❤️ | 少于 1 万只 |

- 家养品种没有可比较的野生存世数量时，按其现实饲养普及度判定：常见家养品种为 `普通`，展示、保育或小众饲养品种可为 `少见`。
- 尚无可靠全球数量的野生物种，依据已知分布范围、稳定性与保护资料作保守判断；不能仅因外形独特或公众少见而上调档位。
- 稀有度是招募门槛、来访权重和卡牌心数的单一来源，不再为产品节奏单独调整档位。

### 现实分布规则

- 家养品种写法：`家养品种，原产/培育于...，现作为宠物/展示/牧场饲养分布于...`。
- 野生物种写法：`野外原产/分布于...，主要生境为...，保护状态为...`。
- 不确定保护状态时写“需复核”，不要硬写濒危、近危或无危。
- 同一物种变体不要在正式条目中写“同 Cxx”；正式 Buddy 必须能独立阅读。

### 文案规则

- 性格摘要使用一句话，结构优先为“核心性格 + 陪伴角色定位”。
- App 内一句介绍可以沿用性格摘要，也可以使用“这个 + 物种 + 性格 + 是...”的用户可见文案。
- 气质补充必须解释为什么归入该气质，而不是重复性格摘要。
- 文案避免负面标签直接伤害用户感受；例如高敏不是“难带”，而是“感受强、需要更多安抚”。

### 立绘提示词规则

- 只描述姿态和动物特征，不描述画风、材质、镜头、光效、背景或场景。
- 只允许站姿或坐姿，不四脚着地。
- 不出现道具、文字、icon、特效、树木、自行车、食物、玩具、雪花等外部元素。
- 必须保留核心动物特征，例如耳朵、尾巴、口鼻、翅膀、花纹、短刺、尾鳍等。
- 动作应适合 6 到 12 个月宝宝比例的拟人动物，避免攻击性、恐怖感或过强成人化姿态。

### 资产规则

- Asset 名称统一为：`companion_<english_name_lowercased>_portrait`。
- 目标路径统一为：`BBB/Assets.xcassets/buddy/companion_<english_name_lowercased>_portrait.imageset/`。
- 推荐主文件名统一为：`companion_<english_name_lowercased>_portrait.png`。
- 如果英文名后续调整，资产名也必须同步调整；因此正式编号前应先定稿中文名和英文名。

## 资产命名规范
