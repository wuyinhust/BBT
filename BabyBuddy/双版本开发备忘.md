# BabyBuddy 双版本开发备忘

更新时间：2026-06-05（Asia/Shanghai）

## 当前分支

- 当前审核分支：`appstore-review`
- 来源分支：`codex/create-infant-activity-tracking-ios-app`
- 目标：在不影响完整产品线继续开发的前提下，收敛出 App Store 审核版。

## 两个版本的定位

### 完整开发版

- 保留完整成长页：手帐、相册、徽章册、Playlist、备忘录。
- 陪伴页继续承载完整陪伴/直播岛/来访伙伴/昨日奖励等体验。
- 记录页保持当前完整记录能力。
- 后续产品实验、复杂玩法、新功能优先进入完整开发版。

### App Store 审核版

- 成长页只保留：
  - 相册
  - 徽章册
- 陪伴页对外呈现为“伙伴广场”。
- 记录页不变。
- 审核版只做必要的产品收敛、文案收敛和审核风险控制，不在该分支继续扩展复杂玩法。

## 推荐实现方式

不要长期维护两套复制代码。使用“同一套代码 + 版本配置”的方式。

建议新增集中配置：

```swift
enum AppVariant {
    #if APPSTORE_REVIEW
    static let isAppStoreReview = true
    #else
    static let isAppStoreReview = false
    #endif
}
```

审核分支或审核 Build Configuration 打开 `APPSTORE_REVIEW`。完整开发版默认不开。

## 代码落点

### 1. 成长页

在 `GrowthBook` 附近增加可见集合：

```swift
static var visibleCases: [GrowthBook] {
    AppVariant.isAppStoreReview ? [.album, .badge] : GrowthBook.allCases
}
```

然后把 `GrowthView` 内用于轮播、分页点、初始索引的 `GrowthBook.allCases` 改为 `GrowthBook.visibleCases`。

注意：审核版默认选中书本应改成 `.album`，不要继续默认 `.handbook`。

### 2. 陪伴页

优先做展示层收敛，不删除底层数据和 store。

- `RootTab.companion.title` 在审核版返回“伙伴广场”。
- `CompanionLiveView` 的标题、副标题、按钮和空状态文案改为广场语义。
- 如果需要更干净，可以新增 `CompanionSquareView`，但应复用现有 `BabyCompanion`、`CompanionStore`、`CompanionRecruitmentStore`，不要复制数据源。

### 3. 记录页

`RecordHomeView` 不加版本判断，不做审核版差异。

## 合并规则

- 通用 bugfix：先在完整开发分支修，再合并或 cherry-pick 到 `appstore-review`。
- 审核专用收敛：只留在 `appstore-review`，不要反向合并回完整开发分支。
- 配置化能力本身：可以合回完整开发分支，但默认值必须保持完整版本行为。
- 冲突处理原则：优先保留完整开发版业务能力，用 `AppVariant` 控制审核版展示，不用删除主线能力。

## 提交建议

审核分支建议拆成小提交：

1. `Add app variant configuration`
2. `Limit growth books for App Store review`
3. `Rename companion tab to square for review`
4. `Polish review variant copy`

每个提交后至少跑：

```sh
swiftc -parse BBB/*.swift
plutil -lint BBB.xcodeproj/project.pbxproj BBB/Info.plist BBB/BBB.entitlements BaByBuddyWidget/Info.plist BaByBuddyWidgetExtension.entitlements
```

完整 `xcodebuild` 如果本机环境不再卡住，再作为最终验证。
